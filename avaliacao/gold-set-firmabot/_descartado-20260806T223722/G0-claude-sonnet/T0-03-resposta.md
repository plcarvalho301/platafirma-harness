**Definição**

Segundo Bass, Clements e Kazman (*Software Architecture in Practice*), a definição adotada pelos autores é:

> "The software architecture of a system is the set of structures needed to reason about the system, which comprise software elements, relations among them, and properties of both."

Isto é, arquitetura de software é o conjunto de estruturas necessárias para raciocinar sobre um sistema — elementos de software, as relações entre eles e as propriedades de ambos. Os autores fazem questão de contrastar essa definição com outras que falam em "decisões de design iniciais" ou "decisões maiores": para eles isso não serve como definição, porque nem toda decisão arquitetural é tomada cedo (especialmente em projetos ágeis) e nem toda decisão tomada cedo é arquitetural. Estruturas, dizem, são mais fáceis de identificar objetivamente do que "decisões importantes".

*(Transcrito/derivado de: Software Architecture in Practice — Bass, Clements, Kazman, capítulo "Introduction", seção 1.1 "What Software Architecture Is and What It Isn't".)*

**Uma segunda formulação, complementar**

*Continuous Architecture in Practice* (Erder & Pureur) traz, na seção "What Do We Mean by Architecture?", a definição do IFIP Working Group 2.10:

> "Software architecture refers to the fundamental structures of a software system and the discipline of creating such structures and systems. Each structure comprises software elements, relations among them, and properties of both elements and relations."

Essa mesma fonte acrescenta que a arquitetura funciona como uma metáfora análoga à arquitetura de edifícios — um blueprint para o sistema e para o projeto de desenvolvimento — e que trata de escolhas estruturais fundamentais, caras de mudar depois de implementadas. O trecho também cita que a documentação da arquitetura facilita a comunicação entre stakeholders, registra decisões iniciais de alto nível e permite reúso de componentes de design entre projetos. O trecho estava em transição para citar também a definição da ISO/IEEE, mas o texto que chegou foi cortado logo no início dessa segunda definição ("Architecture: Fundamental concept...") — não dá para transcrevê-la com segurança.

*(Transcrito de: Continuous Architecture in Practice — Erder & Pureur, "Why Software Architecture Is More Important than Ever", seção "What Do We Mean by Architecture?".)*

**Observação**

As duas fontes convergem no núcleo da definição (estruturas + elementos + relações + propriedades), o que dá certa robustez a essa formulação — mas isso é uma leitura minha ao comparar as duas fontes, não uma afirmação explícita em nenhuma delas. As demais fontes recebidas neste turno ([1], [4]–[8]) não trazem definição do conceito: são material de índice/capa, sumário de capítulo, ou trechos sobre escopo do livro e percepção de arquitetos — não sustentam afirmação sobre o que é arquitetura de software.
